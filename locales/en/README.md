# Personal wiki

This project is a personal wiki created with `wizki init`. It follows the
**LLM Wiki** pattern: the original sources (PDFs, articles, photos, tables,
books) stay untouched, and an assistant (Claude Code) turns them into linked
markdown pages: one per source, one per topic, one per entity. The pages are
updated with every new source, so the cross-references are already there,
contradictions are already flagged, and the overview reflects everything read
so far.

Three roles:

| Who | What they do |
|---|---|
| **You** | Put sources in `library/inbox/`, ask questions, approve the assistant's plans |
| **The assistant** | Reads the sources, writes and updates the pages, flags contradictions and gaps |
| **wizki** | Files the originals, extracts the text, rebuilds the index, keeps the log, runs the mechanical checks |

The rules the assistant follows are in `CLAUDE.md`: it is the wiki's schema,
and it can evolve with use.

> This file, `CLAUDE.md` and `.claude/commands/` are generated by wizki:
> `wizki upgrade -apply` replaces them with the current version, saving the old
> ones as `<file>.bak`. To write notes about the wiki, use `library/overview.md`.

## Layout

    ./
    ├── README.md             this file
    ├── CLAUDE.md             the schema: the rules for the assistant
    ├── .claude/commands/     Claude Code's /ingest and /lint commands
    ├── .git/                 the project's history
    └── library/              the wiki
        ├── inbox/            sources to process
        ├── raw/              originals, NEVER to be modified
        │   ├── pdf/          PDFs
        │   ├── doc/          .md, .txt, .html
        │   ├── assets/       images (in <source>/ when attached to a document)
        │   ├── data/         .csv, .tsv, .json
        │   ├── epub/         .epub books
        │   └── text/         text extracted from the originals
        ├── sources/          one note per source: summary, topics, entities
        ├── topics/           one hub per topic: cumulative synthesis of all sources
        ├── entities/         one page per entity: person, organization, place, law, work, event
        ├── analyses/         answers to questions, saved because they are reusable
        ├── overview.md       overview: thesis, main themes, open questions
        ├── index.md          catalog of every page (generated, don't edit it)
        ├── log.md            activity log (append-only)
        └── .zk/              zk configuration and templates

- **`library/raw/`** is the safe: `wizki extract` copies the original and the
  extracted text there, and refuses to overwrite. Nobody edits these files.
- **Every page** has `title:` and `summary:` in its frontmatter (one line, the
  one shown in the index). Sources also have `id:` (first 8 chars of the
  original's SHA-256), `date:` (day of ingestion), `published:` (the document's
  date: `YYYY-MM-DD`, `YYYY-MM`, `YYYY` or `unknown`) and `raw:` (path of the
  original). Entities have `type:`.
- **Tags** `#topic` live only in source notes; topics, entities and analyses
  have no tags.
- **Links** are always wikilinks with path and title:
  `[[topics/school|school]]`, `[[sources/1a2b3c4d-circular|Circular 12/2026]]`.
  Never a bare `[[school]]`: zk would resolve it with a partial match on the
  file name.

## Requirements

- **wizki** in the `PATH`: from the wizki repository, `go install .` (it ends
  up in `$(go env GOPATH)/bin`). Run it again after every wizki update.
- **zk**, **git**, **poppler** (`pdftotext`, `pdftoppm`) and **tesseract** with
  the OCR language (`ita` by default; use `-ocr-lang eng` for English sources).
- **Claude Code** (`claude`).

`wizki deps` checks what is missing and proposes the command to install it.

**Every command runs from the project root**, the folder holding this file:
wizki finds the wiki in `library/` on its own. From another folder, point to
the project with `wizki -root <project> ...`.

Always run zk with `-W library`: `zk -W library ...`. The `ZK_NOTEBOOK_DIR`
variable might point to another notebook.

## Everyday work

Open Claude Code in the project root:

    claude

### 1. Adding a source

1. Put the file in `library/inbox/`. Formats: PDF (scans too, with OCR), `.md`,
   `.txt`, `.html` (with its local images next to it), images, `.csv`, `.tsv`,
   `.json`, `.epub` (without DRM). Save Word documents as PDF first.
2. In Claude Code type `/ingest`: it offers the waiting sources, in the order to
   ingest them. Or `/ingest @library/inbox/<file>` (Tab after `@` completes the
   name).
3. The assistant:
   - runs `wizki extract library/inbox/<file>`, which moves the original to
     `library/raw/<type>/` and the text to `library/raw/text/`, and prints the
     path of the text and the source's id;
   - reads the text, picks 1-3 topics (nouns, lowercase, singular, reusing the
     existing ones) and the entities the source says something substantial
     about;
   - **shows you the plan** (title, date, key points, topics, entities) and
     waits for your confirmation: this is when you tell it what to stress;
   - writes the source note, updates topics, entities and `overview.md`,
     rebuilds `index.md` and writes to the log.

   A single source may touch 10-15 pages: that's normal.

If `extract` stops, the source stays in `library/inbox/`:

| Exit | Meaning | What to do |
|---|---|---|
| 3 | No text (empty file, PDF unreadable even with OCR, EPUB with DRM) | Check the file or get a better copy |
| 4 | OCR not available (tesseract or its language is missing) | `wizki deps`, then try again |
| 5 | Source already ingested (same content, even under another name) | Delete the copy from the inbox |
| 6 | Network `raw/` unreachable | Mount the share and try again |

### 2. Asking questions

Ask the assistant in plain language. It starts from `library/index.md` and
`library/overview.md`, then reads topics, entities and sources, and answers
citing the pages. If the answer is reusable (a comparison, a synthesis across
topics) it offers to save it in `library/analyses/`; the analysis is then
linked from the topics and entities it is based on.

To search on your own:

    zk -W library list --match "<terms>"           # in the pages (prefixes too: "lesson*")
    zk -W library by <topic>                       # sources with that tag
    zk -W library list --link-to topics/<topic>.md # who links a topic
    zk -W library topics                           # every topic, with counts
    rg -i "<terms>" library/raw/text/              # in the text of the sources

### 3. The check-up

Every now and then, type `/lint` in Claude Code. First the mechanical checks
(`wizki lint`, exit 1 if there are warnings): tags without links and vice
versa, plurals or synonyms among topics, orphan notes, topics with a single
source, missing or duplicate `id:`, missing or malformed `summary:` and
`published:`, broken links, topics that appear together but don't link each
other, analyses with nothing to stand on, a stale `index.md`; as `info`, older
sources ingested after newer ones and analyses that got new sources.

Then the assistant runs the judgment checks (contradictions, superseded
claims, duplicate entities, concepts without a page, gaps a web search could
fill) and presents a report. **It applies nothing without your confirmation.**

## Commands

| Command | What it does |
|---|---|
| `wizki inbox` | Lists the sources in `library/inbox/`, in the order to ingest them |
| `wizki extract <file>` | Files the original in `library/raw/` and extracts its text |
| `wizki index` | Rebuilds `library/index.md` from the pages' frontmatter |
| `wizki log <ingest\|query\|lint> "<title>"` | Appends a line to `library/log.md` |
| `wizki lint` | Mechanical health checks |
| `wizki upgrade [-apply]` | Brings the project up to the current wizki version |
| `wizki raw <folder> [-apply]` | Moves `library/raw/` to a network folder |
| `wizki deps` | Checks the dependencies |
| `wizki slug "<text>"` | Shows how a title becomes a file name |

`extract` options: `-ocr-lang eng+ita` for sources in several languages,
`-no-ocr` to skip OCR on scans.

Notes are created with zk:

    zk -W library new sources --title "<title>" --extra sha=<id> --print-path
    zk -W library new topics --title "<topic>" --print-path
    zk -W library new entities --title "<Name>" --extra type=<type> --print-path
    zk -W library new analyses --title "<title>" --print-path

Entity `<type>`: `person`, `organization`, `place`, `law`, `work`, `event`.

## Maintenance

### After updating wizki

    go install .              # in the wizki repository
    wizki upgrade             # here: shows what it would do
    wizki upgrade -apply      # does it

It creates what is missing, replaces the `library/.zk/` files, this README,
`CLAUDE.md` and `.claude/commands/` when they differ from the embedded ones
(saving the old one as `<file>.bak`) and rebuilds `library/index.md`. It never
touches notes. Afterwards, compare the `.bak` files with the new ones, carry
over any customization by hand (`CLAUDE.md`'s too), delete the `.bak` files and
run `wizki lint`: old notes may lack the newer fields.

### Originals on a NAS

    wizki raw /mnt/nas/wiki          # shows the plan
    wizki raw /mnt/nas/wiki -apply   # runs it

It copies the originals verifying their SHA-256, keeps the old `raw/` as
`library/raw.local-<date>` (delete it by hand after checking), turns
`library/raw` into a link to the remote folder and writes the `.wizki-raw`
marker there. The `raw/...` paths in the notes stay valid. If the share is not
mounted, `extract` and `upgrade` stop with exit 6 without touching anything;
reading the wiki and asking questions still work.

### History

The project is a git repository (branch `master`). `library/.zk/notebook.db`
is ignored: zk rebuilds it. To see how a page changed:

    zk -W library hist topics/<topic>.md

## Rules

- Never modify `library/raw/`.
- Never edit `library/index.md` by hand: rebuild it with `wizki index`.
- `library/log.md` is written only with `wizki log`, append-only.
- No thematic folders or symlinks: per-topic views are zk queries. The only
  link allowed is `library/raw`, created by `wizki raw`.
- Never two pages for the same entity: the title is the most common full name,
  acronyms and variants go in the "Description".
- Dates matter: a newer source updates superseded data; an older one adds
  historical, dated information without overwriting.
- What comes from the web enters the wiki only as a new source in
  `library/inbox/`.
